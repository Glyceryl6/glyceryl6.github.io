# Astral Mod Forge：独立 MOD 导出思路

**星航 MOD 工坊（Astral Mod Forge）**是一项 Rider 插件和 Java CLI 的工程实验，用于从 C# 项目选取一组相关源文件，生成独立项目并运行构建检查。这里整理它的通用设计，不分发私有工程代码。

## 导出流程

1. 在源工程中选择类或源文件，审查依赖展开结果。
2. 确认类之间的静态调用、初始化入口、反射与资源引用。
3. 为生成工程指定独立的 ID 和程序集名称。
4. 将可确认的设置与本地化资源隔离到生成工程，避免复制整个宿主界面。
5. 选择是否保留生成的 C# 源码；编译必须真实成功并产出 DLL 才算构建成功。
6. 检查日志、依赖清单、许可证和第三方依赖，必要时在合法环境下进一步测试。

## 当前需要注意的边界

- 静态依赖分析难以自动覆盖反射、事件、委托、代码生成与运行时注入。
- 配置内嵌意味着不能假设仍保留运行时可修改的 `Config.Bind()` 行为。
- `ProjectReference` 不一定传递所有非托管或游戏代理 DLL，必须检查设计时和真实构建日志。
- 不能把“导出 C# 文件成功”显示为“编译出 DLL 成功”。
- Rider 插件应使用**真实 JetBrains SDK**构建，不应将模拟的 IntelliJ API 类打包进正式安装包。

该工具以前的版本曾出现过 `Project` 接口二进制不兼容、NuGet 包源缺失和过度收集语言键的问题。相关经验已经融入此页，并不承诺任何未公开版本已在用户环境中通过真实加载测试。

参考：[JetBrains 插件开发文档](https://plugins.jetbrains.com/docs/intellij/welcome.html)、[构建和 NuGet 排查](unity/build-and-references.md)。
