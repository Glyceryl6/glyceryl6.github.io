# 原生对象生命周期、线程与异常

## 原生对象不是普通 C# 对象

`IntPtr` 是地址值，不提供对象所有权或存活保证。Unity 场景切换、窗口销毁、热更新重建以及资源释放，都可能使之前缓存的地址失效。

- 访问前检查对象生命周期与当前场景。
- 短期保活工具只能管理其职责范围内的引用，不保证场景对象永不销毁。
- `Ready()` 表示某个基础组件就绪，并不等于目标窗口或资源永远有效。
- 使用完成后及时释放，避免跨帧持有无效的原生句柄。

## 主线程约定

Unity UI 和 FairyGUI 的原生操作一般应在相应主线程生命周期执行；不要在 `Task.Run`、监听回调、定时器等背景线程直接操作界面对象。

## 问题定位

| 错误 | 最先确认 |
|---|---|
| `ObjectDisposedException` | 是否重复访问已关闭的窗口 |
| `AccessViolationException` | 指针、ABI、线程、桥接版本是否匹配；停止重试 |
| `MissingMethodException` | SDK 与宿主的实际程序集身份是否一致 |
| `TypeLoadException` | 编译时引用的类型是否已迁移或改名 |
| 界面不显示 | 资源和窗口的加载顺序，是否在正确生命周期调用 |

`NativeSdkServices` 旧版使用静态共享回调。多个 MOD 同时配置该服务可能相互覆盖；如需跨插件共享，建议将上下文隔离为每插件实例，而不是在每帧重复注册全局回调。

更多错误参见[构建与运行排查](unity/troubleshooting.md)。
