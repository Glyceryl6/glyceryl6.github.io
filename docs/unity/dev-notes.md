# 开发手记：做这个 MOD 时的想法与取舍

这一页记录的是开发过程中的判断，不是 API 文档。**每一条都对应过一个具体问题**：为什么某个功能最后没做、为什么明明能实现却选择回退、为什么界面要长成那样。

如果只看结论，很容易觉得这些选择是理所当然的；实际上每一条背后都有一版被推翻的实现。

## 一、先分清“能做到”和“该做”

### 服务器决定的事，客户端改不了

同一个“解锁”需求，要拆成两种情况：**客户端只是没显示**，还是**服务器根本没有返回**。前者可以做，后者做出来只会让本地和别人看到的不一致。

判断方法很朴素：改完之后，另一个客户端看到的结果变了吗？没变，说明你改的是表现层。

### “源码层面可实现”不等于“实机可用”

交付时把功能分成三类标注：已验证、实验性、未验证。不把没跑通的东西写成“已支持”，否则下一个接手的人要花更多时间分辨哪句是真的。

### 宁可不修外观，也不做高危原生写入

有一版为了修正勾选框的点击区域，直接写了原生命中区字段。结果它绕过了 C# 异常处理，进程直接被带走。

**结论：闪退的优先级高于外观。** 该功能整体撤回，只保留安全的 `touchable`、`opaque` 这类属性设置。

## 二、几个被放弃的方案

| 想做的事 | 最终做法 | 放弃的方案与原因 |
|---|---|---|
| 统计窗口外观 | 自绘外壳复刻视觉，复用原版的记录行、箭头与关闭控件 | 克隆整套原生窗口：依赖资源包驻留，会出现两套尺寸不一致的外观，还偶发 `AddChild` 空对象 |
| 设置页滚动 | 原生 `ScrollPane` + `GScrollBar` | “把音量滑块旋转 90° 当滚动条”——没有真实裁剪和滚轮行为；把原生页面当容器——页面自带控制器，布局会被接管 |
| 自动行走 | 点选可达终点，之后每到岔路按原版箭头逐段移动 | 一次性提交整条路径：原版协议本来就是逐段上报下一地块，整段提交不符合协议 |
| 字体描边 | 放弃原版同款描边，保证汉字完整显示 | 强行写 IL2CPP 字体字符串指针：出现 `AccessViolationException`，`try/catch` 兜不住 |
| 本地化键名 | 改成点分命名空间，如 `astralparty.stats.*` | 用中文原文当查找键、或沿用某个 MOD 的专属前缀——通用 SDK 不该带某个 MOD 的身份 |
| 商店自动购买 | 直接读商品数据结构（价格、货币类型） | 扫描界面文字：无法处理折扣与已售罄，价格不明确时不该替用户决定 |

这些方案的共同点是：**它们都能“跑起来”，但都会在某个版本或某个场景下变成新的故障源。**

## 三、界面上的经验

- **不要拿原版页面当容器。** 原版设置页、音量页自带 Controller、Gear 和资源布局，`SetVisible` 不代表你的子控件会显示。正确做法是只借样式，自建视口。
- **不要在原版文字上叠第二层。** 原生动画只驱动原版文字，独立叠加的文本框必然错位。
- **复用控件要连默认文案一起改。** 截图目录输入框复用了兑换码输入框，占位文字还写着“在此处输入您的兑换码”。
- **悬停提示跟随原版。** 用 `onRollOver` 高亮，并调用原版的消息组件显示短语，比自绘 Tooltip 稳。
- **展开/收起是必要的。** 面板做大之后会压住快捷按钮与 Buff 列表；原版切页不给新页播动画，需要自己补一段短促的滑入渐显，且不要留下长期 Tween。

## 四、关于“用户会怎么用”

- **调参不应要求重启。** 布局参数外置为配置文件，运行时检测修改；但必须加完整性检查、范围校验和失败回退，写坏一个值不能把整页布局搞崩。
- **翻译坏掉也要能看。** 语言文件解析失败时保留上一份有效内容；缺键时回退到内置中英文，否则界面会直接显示 `astralparty.xxx` 这样的键名。
- **空值不要伪装成数据。** 没有记录的统计显示 `—` 而不是 0；不确定的拥有状态不要伪造。
- **快捷键不能抢原版按键。** 曾经和原版标记键冲突，最后改用组合更冷门的键；快捷键因为“不在对局”被跳过时，要写日志说明原因，否则用户只会觉得“没反应”。
- **误触比报错更伤体验。** 只在窗口区域设 `opaque` 时，点击窗口旁边的空白会穿透到后面的活动页；最终加了独立的全屏透明命中层，并让它跟随窗口生命周期创建销毁。

## 五、工程与交付

- **通用算法进 SDK，版本相关的原生调用留宿主。** 排版计算、统计注册表这类纯逻辑可以复用；创建 FairyGUI 对象、操作 IL2CPP 指针的代码留在适配层，否则 SDK 会被绑死在某个游戏版本上。
- **MOD、SDK、附属包分开提交。** 一个提交只处理一个主题，既方便 review，也方便 `git revert`；整包覆盖还会冲掉用户的本地配置。
- **只交付增量文件。** 覆盖式更新不会删除已移除的文件，必须按清单清理，否则旧类会参与编译。
- **先记录，再修改。** 改列表、改统计之前，先输出“总数 / 标记数 / 变化前后”的只读审计，用数字判断问题出在配置、过滤还是资源。

## 六、几条反直觉的结论

1. **缺字要按字体层级判断，不是字库缺字。** 设置界面用的是一套**单独的、带黑色描边的字体**；它同样只在该字被用到时才补字形，所以个别字会短暂缺失。其他界面用的是原始字体库、只改了颜色，从来没有出现过缺字。看到缺字时先确认它出现在哪个字体层级，不要急着换字库或改字体。
2. **`opaque=true` 不等于挡住点击。** 它只保护自身矩形，窗口之外的区域仍会穿透。
3. **回放文件很小，因为它不是视频。** 那是命令流（命令 ID + 负载长度 + 负载），改扩展名永远不会变成 MP4。
4. **在 Bundle 里搜 `MZ` 或 `.dll` 找不到程序集。** 缓存 Bundle 通常经过分块压缩，必须先解码 `TextAsset` 才能判断是不是有效程序集。
5. **引用了热更新 DLL 也消不掉反射。** 编译期拿到类型，不等于运行时能操作对象；仍要经过宿主适配器，并处理程序集加载顺序。
