# 实践中的坑

这一页不是“注意事项清单”，而是**故障记录**：每一条都来自真实迭代里出现过的现象，按“现象 → 根因 → 做法”整理。遇到相似症状时可以直接对照，不需要从日志第一行开始猜。

括号里标注的是这个项目内部的更新记录编号，方便自己回溯，不影响阅读。

> 这些经验来自一个具体项目，不保证在其他游戏或其他 HybridCLR 版本上完全一致。把结论当成“值得先检查的地方”，而不是“必然如此”。

## 一、运行时与 Hook 时机

### 反射拿到的指针是零

- **现象**：启动早期的日志里出现 `TypeLoadException`，或按名解析 `FairyGUI.GObject` 失败；主界面元素与设置页迟迟不出现。
- **根因**：热更新程序集由游戏运行时在启动过程中加载，插件初始化往往**早于**它就绪。此时按类名查找只会得到零指针，注册失败会连带整条初始化链断掉。
- **做法**：解析失败不要抛异常终止，改为定时重试（例如每 2 秒一次），连续失败约 24 秒后再输出第一条诊断日志。把“还没到时候”和“真的不存在”区分开。

### 找到类却 Hook 不到

- **现象**：类和方法的指针都能取到，装完 Hook 却没有回调；或者一装就闪退，还影响到大量无关方法。
- **根因**：热更新 DLL 里的方法不一定是解释执行的；解释器方法共用 AOT 侧的 thunk（桥接入口），多个方法指向同一个地址，按地址去重就会互相踩踏。
- **做法**：安装前**整组解析**，要求运行时明确把目标识别为 HybridCLR 解释方法，只在策略匹配（例如专用的解释器桥接 detour）时安装；同时校验 `MethodInfo` 的归属，不要拿另一个程序集里的同名方法凑数。

### 重复安装与“半装”状态

- **现象**：日志里反复出现 `Address already hooked`，或每十秒重试同一条 warning；部分功能生效、部分不生效。
- **根因**：被拒绝的 Hook 没有被记为终止失败，于是永远重试；安装过程不是事务性的——前面的方法装成功、后面失败时，已经改写的入口仍然残留。
- **做法**：把一组 Hook 当成事务：任何一步失败就撤回本组新建的 Hook，并停止该组在本进程内重试；回滚失败时保留原委托并要求重启；首次安装早于就绪时，用一次性补装列表兜底。

## 二、UI 框架与渲染

### 设置页整页空白

- **现象**：窗口和选项卡都在，但开关、输入框、滑块全部消失。
- **根因**：直接把原版设置页的屏幕页或音量页当作 MOD 内容的宿主。这些页面仍受 Controller、Gear 和资源布局控制，`SetVisible` 并不能保证自定义子控件可见。
- **做法**：只借用原生的边框与样式，自建 `GComponent` 视口，并用游戏已有的溢出裁剪（`SetupOverflow(Hidden)`）限制内容范围。

### 标题错位与中文缺字

- **现象**：标题文字和底图不同步、最后一个字被截断；或者固定几个汉字永远不显示。
- **根因**：独立叠加的 `GTextField` 不在原生切换动画（Switchin / Switchout）的目标里；`textWidth` 在赋值并更新尺寸之前不可信；`AutoSize.Shrink` 会自动缩小字号；`TextFormat.CopyFrom` 不会复制描边、字形膨胀这类材质参数。
- **做法**：改原生按钮自带的文本框（`GetTextField()`），复用它的动画与排版；宽度按实测值加左右留白；缺字先确认字体覆盖范围，再调偏移与字号。

### 点击穿透，或关窗后仍然吞点击

- **现象**：设置页打开时还能点到背后的原版入口；或者窗口关掉后按钮仍然点不动。
- **根因**：原版设置窗只覆盖屏幕右侧，给窗口本身设 opaque 保护不到左侧；而补上去的全屏透明命中层如果没有跟随开窗、关窗、切场景一起销毁，就会长期挡在最上层。
- **做法**：在根画面、窗口下方放一个 opaque 且可接收触摸的透明组件，并让它的生命周期与窗口、场景、分辨率变化同步；ESC 录键与退出共用同一个 `OnKeyDown`，只有在能安全挂接时才拦截，否则换用 Backspace 这类不冲突的键。

## 三、生命周期与内存

### 返回大厅后控件只剩文字

- **现象**：对局结束回到大厅再打开设置，按钮、勾选框、背景图消失，只剩文字。
- **根因**：窗口释放与资源包卸载（`Dispose` / `RemovePackage`）会连带卸载 FairyGUI 纹理，而 MOD 保存的克隆控件引用随之失效。
- **做法**：保存**资源包与根对象的世代标识**而不是裸指针；每次打开前校验场景、包指针与释放状态，失效就销毁重建，而不是复用旧对象。

### 按钮重复叠加，最后变成白块

- **现象**：统计入口越开越多，最后整块变白；或日志报原生列表的第 16 个控件缺失。
- **根因**：重置时只清了字段指针，没有把子对象从仍然存在的原生父容器里移除；`AddChild` 会把对象从旧父容器移走，导致按旧索引读取时整体前移错位。
- **做法**：给自建控件唯一名称，创建前清理同父容器下的同名残留；移除前校验父容器身份；多个控件按索引**逆序**挂载并逐个校验句柄。

### 对象数量暴涨

- **现象**：对局中已加载对象从两万级涨到四百多万，进程专用内存持续上升直到卡死。
- **根因**：多个周期服务同时在跑，单看一条原生回调栈无法判定谁在制造对象；而盲目销毁游戏仍在使用的 UI 会造成空白和崩溃——两者都会让排查更糟。
- **做法**：按功能组做隔离对照（最小启动 / 仅初始化 / 单组 / 小组合），同时记录进程专用内存、工作集与托管堆近似值；不强推 GC、不主动释放游戏对象。

## 四、构建与依赖

### 找不到 NuGet.Config

- **现象**：构建脚本在还原之前就报 `NuGet.Config not found`，即使本地已经还原过、而且禁止联网还原。
- **根因**：脚本假设共享父目录一定有配置文件，把“可选输入”当成了“必需输入”。
- **做法**：按共享父目录 → 项目目录 → SDK 目录依次查找，找到才传 `--configfile`；都没找到就沿用系统默认源；只有显式指定却不存在时才报错。

### 编译引用到了错误的后端

- **现象**：编译能过，进游戏却缺类型或缺方法；或者和其他 MOD 行为不一致。
- **根因**：定制包与上游包的 **Package ID 不同，但 DLL 文件名与命名空间相同**；被排除的上游包仍可能留在依赖图里，最终用哪一份取决于实际解析路径。
- **做法**：对上游引用设 `ExcludeAssets=all`，并在解析引用后断言实际来源与路径；同时记住，编译修好不等于运行时加载了正确的后端，别再往插件目录塞一份 `Runtime`。

### 两份辅助程序集与重复类型

- **现象**：启动报程序集版本冲突，或编译报 `CS0101` 同名类型重复定义；个别功能悄悄走了旧逻辑。
- **根因**：辅助程序集既被嵌入主 DLL，又被 `AssemblyResolve` 另加载一份；目录迁移后旧文件没删，新旧同名类型同时参与编译。
- **做法**：用白名单资源加 `AssemblyResolve` 按需加载，优先复用已加载且版本匹配的实例，冲突时**明确报错**而不是加载第二份；先构建 SDK 再构建 MOD，比对暂存 DLL 的 SHA-256，并按清单清掉旧路径。

## 五、游戏版本更新之后

### 本地化串到了别的表

- **现象**：更新后角色名显示成卡牌名，控制台刷“某张表没有该 ID”。
- **根因**：游戏用顺序枚举表示字符串表类型，更新插入新值后序号整体漂移，MOD 里记着的旧编号指向了另一张表。
- **做法**：把表 ID 集中到适配层，调用前先确认对应字典里确实有这个键；取不到就留空，而不是让每个 ID 各刷一条报错。

### 找不到 `get_` 方法

- **现象**：读取统计数值时抛 `MissingMethodException`，界面空白。
- **根因**：热更新里的成员是 public 字段而不是属性，反射按属性去访问自然找不到 getter。
- **做法**：先用元数据判断成员种类——字段走字段读取，属性才走 getter——并对返回值做类型校验。

### 字段偏移读错与控件“搬家”

- **现象**：新建的弹层拿到空组件、读出的字段全是默认值；或者某个入口点了没反应。
- **根因**：`UIPackage` 创建的只是通用 `GComponent`，在原生绑定（BindAll）完成之前，不能按游戏子类的字段偏移去解释它；游戏更新也可能把控件挪到别的面板。
- **做法**：只用子节点索引加实际类型检测，结构不符就自动降级为本地布局；改任何原生控件前，先确认它真正由哪个面板持有。

## 六、发布与用户环境

### 覆盖 DLL 之后行为没变

- **现象**：换了新 DLL，启动日志还是旧版本，甚至出现已经删掉的类名。
- **根因**：正在运行的进程不会因为磁盘文件被覆盖而替换已加载的程序集；旧进程里被改写的入口也不会自动还原。
- **做法**：必须**完全退出游戏**再更新并重启；新旧构建不要放在不同子目录并排保留（否则可能加载到旧的那份）；出现旧类名时先查启动日志里的加载路径。

### 改配置没生效，或者更糟

- **现象**：手动编辑布局或语言文件后界面没变化，甚至整页错乱。
- **根因**：编辑器保存过程中文件处于半写入状态；用户也可能删掉某个键。解析器如果接受不完整配置，就会用半套参数重建界面。
- **做法**：要求全部键存在且合法才应用；非法、重复或缺失时保留上一份有效值，并输出明确的拒绝日志。

### 崩溃与卡顿无法归因

- **现象**：只拿到一句空引用或一片卡顿，无法判断是哪个功能、哪一帧。
- **根因**：关键操作前没有留下标记，异常栈缺少 Unity 侧上下文；同时开着多个功能时变量太多。
- **做法**：在关键操作点同步写一行标记文件，崩溃后取标记末行与 `Player.log` 末尾几十行；开启主线程耗时统计（例如每 30 秒报告最大耗时与超阈值的帧数），并用关闭 MOD 的对照测试，一次只改一个变量。

## 如果只记五条

1. **Hook 之前先确认两件事**：目标方法已经就绪，且确实是解释执行；整组装、失败就跳过，不要反复重试。
2. **不要用自建层去改原生 UI**：改原生组件本身，只在克隆体上解绑，别在原版控件上叠图层。
3. **原生指针会随场景失效**：缓存即崩；也不要主动释放游戏仍在使用的对象。
4. **覆盖 DLL 不等于生效**：任何结论都要冷启动复测，新旧构建不能并存。
5. **编译期和运行期的 Interop 是两件事**：锁版本、验来源，SDK 先构建再构建 MOD。
