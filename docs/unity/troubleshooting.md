# 构建与运行时常见问题

排错顺序建议为：**读取第一条真正错误 → 确认项目环境 → 还原依赖 → 检查版本 → 最后审查源码**。大量后续错误常是第一个基础引用失败带来的连锁反应。

| 错误 / 现象 | 常见根因 | 首先检查 |
|---|---|---|
| 数千个 `UnityEngine` 标红、`CS0246` | 代理 DLL 缺失、引用未导入 | `TargetFramework`、设计时 MSBuild、代理目录 |
| `NU1101` | NuGet 源缺失或包版本不匹配 | `NuGet.Config`、`dotnet nuget list source` |
| `CS0012` | 缺失传递程序集 | 找到报错中要求的程序集名，核对直接引用 |
| `CS1705` / `NU1605` | 依赖版本冲突／降级 | 统一包版本；不要用强制忽略掩盖问题 |
| XML 导入异常 / `<Error>` | `.targets` 中使用了非法结构 | `<Error>` 是否写在 `<Target>` 中 |
| `FileNotFoundException` | 运行时搜索路径或程序集缺失 | 插件目录和实际装载路径 |
| `TypeLoadException` | 目标类型、程序集或方法签名已变 | 编译期与运行时的程序集身份 |
| `MissingMethodException` | Runtime / Common / SDK 版本错配 | 重建全部依赖者，不混用旧 DLL |
| `InvalidCastException` | IL2CPP 代理与托管类型身份不同 | 类型所属程序集及正确转换方式 |
| `AccessViolationException` | 原生指针、线程、ABI 或桥接不匹配 | 停止重复调用；保存日志并回滚 |
| UI 不显示、没有异常 | 场景或资源尚未初始化 | UI 资源是否就绪、生命周期时序 |

## 在 Rider 中定位引用问题

1. 确保打开正确的解决方案，并查看实际加载的项目列表。
2. 查看第一条 MSBuild 和 NuGet 错误，不要被数千处红线干扰。
3. 在正确的项目上下文中执行终端 `dotnet restore`、`dotnet build`，并保留完整日志。
4. 确认 `Directory.Build.props` / `.targets` 的读取顺序；若项目需要本地路径配置，检查它是否被 `.gitignore` 排除后遗失。
5. 确认程序集中没有同时保留同一 SDK 的旧版本和新版副本。

## 运行时异常的判断

C# 编译通过只意味着编译阶段完成，不表示 Unity 对象在任何线程或任意场景都有效。遇到原生内存访问错误，请先停止测试，不要通过无限重试、捕获后继续执行或调整保护设置“绕过”异常。

## 提交问题时建议提供

只提供**自己有权共享**的信息：错误前后的日志行、操作系统、.NET/IDE 版本、构建命令、开源依赖版本及脱敏的文件结构。移除个人游戏账号、令牌、本机敏感路径和游戏专有文件。参考[公开内容边界](about/publication-policy.md)。
